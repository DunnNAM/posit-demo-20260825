# CAQ Posit Connect Cloud demonstrator

Synthetic-data demonstrator showing a Quarto report and a Shiny dashboard
published to Posit Connect Cloud from a single Git repository.

> **All data in this repository is synthetic.** It is generated by a seeded
> script and describes no real patients, facilities or clinical performance.
> Indicator definitions are plausible but not endorsed (see `decision-register.md`,
> D-001 and D-002).

**Current status: Day 1 deployment probe.** `app.R` and `facility-report.qmd`
contain placeholder content whose only purpose is to prove the deployment path.

---

## Repository layout

Flat root by design (D-017) — both Connect Cloud content items share one working
directory, which removes an entire class of path failures after deployment.

| Path | Purpose |
|---|---|
| `app.R` | Shiny dashboard — Connect Cloud primary file |
| `facility-report.qmd` | Quarto report — Connect Cloud primary file |
| `R/` | Shared layer, sourced by **both** products |
| `R/dependencies.R` | Declaration only, never sourced — see below |
| `data/` | Committed synthetic CSVs |
| `data-raw/` | Seeded generator script (Day 2) |
| `renv.lock` | Reproducible environment |
| `project-brief.md` | Scope, data spec, architecture, timeline |
| `decision-register.md` | Every decision constraining scope, data or code (`D-###`) |
| `issues-register.md` | Open risks and unknowns (`I-###`) |

The three register files are working documents. **Any change to scope, data or
architecture is recorded there in the same commit as the code change.**

---

## Conventions

- **Explicit `library()` calls, never `pacman::p_load()`** (D-015). `renv`
  discovers dependencies by static analysis and cannot see packages passed as
  bare symbols to `p_load()`.
- **All function calls namespaced** — `dplyr::filter()`, `ggplot2::geom_line()`
  (D-016). Exceptions: the pipe, and `ggplot2` layer composition with `+`.
- **`R/dependencies.R` is never sourced or run.** It exists so `renv` sees the
  full package set even for packages used in a single code path.
- **No database code.** This project has no `DBI`/`odbc` path (D-003), and the
  repository is public — no server, database, schema or DSN names anywhere,
  including in comments (I-005).
- Indicator logic lives in `R/` and is calculated once. Neither the report nor
  the app computes its own numbers (D-010, I-011).

## Getting started

```r
# Restore the recorded environment
renv::restore()

# Run the app locally
shiny::runApp()

# Render the report locally
quarto::quarto_render("facility-report.qmd")
```

If you add a package, attach it with `library()`, add it to `R/dependencies.R`
if it is used in only one place, then run `renv::snapshot()` and commit the
updated `renv.lock`.

## Day 1 deployment checklist (I-001)

The single highest-risk item in this project is that Connect Cloud will not
serve two content items from one repository sharing one `renv.lock`. **Verify
this before writing any real content.** Record the answers in
`issues-register.md` under I-001 — do not rely on memory.

1. Run `renv::init()` then `renv::snapshot()`. Open `renv.lock` and confirm every
   package listed in `R/dependencies.R` appears. An incomplete lockfile here is
   the failure mode described in I-002.
2. Push to GitHub.
3. In Connect Cloud, deploy `facility-report.qmd` as one content item.
4. Deploy `app.R` as a second content item from the **same** repository.
5. Work through the checks below.

| # | Check | Pass condition |
|---|---|---|
| 1 | Both items deploy from one root `renv.lock` | Both reach "deployed" |
| 2 | Restore completes, and how long it takes | Note the duration |
| 3 | Working directory | Report and app show the **same** value |
| 4 | `source("R/smoke_shared.R")` | Diagnostics table renders in both |
| 5 | `data/smoke_data.csv` readable | "Data file found" is `TRUE` in both |
| 6 | `ggplot2` renders | Chart appears in both |
| 7 | `bslib::font_google("Lato")` | App loads without error |
| 8 | Private repo supported on this tier | Yes / No — affects I-005 |

**If check 3 disagrees between products,** the shared `R/` layer cannot be shared
as designed. Fall back to two repositories with `R/` duplicated, and record the
change against D-017.

**If check 7 fails,** remove `base_font` and `heading_font` from the
`bslib::bs_theme()` call in `app.R`. The app falls back to the Bootstrap default
font stack (D-022).
