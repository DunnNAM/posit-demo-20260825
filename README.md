# CAQ Posit Connect Cloud demonstrator

Synthetic-data demonstrator: a Quarto report and a Shiny dashboard, both published to Posit
Connect Cloud from this single GitHub repository.

> **All data in this repository is synthetic.** It is generated by a seeded script and
> describes no real patients, facilities or clinical performance. Indicator definitions are
> plausible but not endorsed (see `decision-register.md`, D-001 and D-002).

**Status: Day 1 complete.** The deployment path is proven end to end. `app.R` and
`facility-report.qmd` currently contain placeholder probe content; real content
replaces it in place from Day 3 (D-024).

---

## Repository layout

Resolved by Day 1 deployment evidence (D-017). Connect Cloud clones the whole repository and
does not filter the bundle by the manifest's file list, so a **single canonical shared layer**
serves both content items — no duplication, no build step.

| Path | Purpose |
|---|---|
| `app.R` | Shiny dashboard — Connect Cloud primary file |
| `facility-report.qmd` | Quarto report — Connect Cloud primary file. At the root, not in `report/` (D-035) |
| `manifest.json` | **Single root manifest**, union of both products' packages |
| `dependencies.R` | Declaration only — never sourced. See below. |
| `R/` | Shared layer, used by **both** products |
| `data/` | Committed synthetic CSVs |
| `data-raw/` | Seeded generator script |
| `renv.lock` | Local reproducibility. **Not read by Connect Cloud.** |
| `CLAUDE.md` | Conventions and deployment facts, for AI-assisted sessions |
| `HANDOVER.md` | Current state and next task |
| `project-brief.md` | Scope, data specification, architecture, timeline |
| `decision-register.md` | Every decision constraining scope, data or code (`D-###`) |
| `issues-register.md` | Open risks, unknowns and defects (`I-###`) |

The register files are working documents. **Any change to scope, data or architecture is
recorded there in the same commit as the code change.**

## Conventions

- **Explicit `library()` calls, never `pacman::p_load()`** (D-015). `renv` and `rsconnect`
  discover dependencies by static analysis and cannot see packages passed as bare symbols.
- **All function calls namespaced** — `dplyr::filter()`, `ggplot2::geom_line()` (D-016).
  Exceptions: the pipe, and `ggplot2` layer composition with `+`.
- **`dependencies.R` lives at the root and is never sourced** (D-025). It exists so `renv` and
  `rsconnect` see the full package set. It must not sit in `R/`, because Shiny auto-sources
  everything there — which also means every file in `R/` must be safe to source on startup.
- **No database code.** No `DBI`/`odbc` path (D-003). This repository is **public** — no
  server, database, schema or DSN names anywhere, including in comments (I-005).
- **Indicator logic lives in `R/` and is calculated once.** Neither product computes its own
  numbers (D-010, I-011).

## Local development

```r
renv::restore()      # restore the recorded environment
shiny::runApp()      # run the app
```

```
quarto render facility-report.qmd
```

Use the Quarto CLI or RStudio's Render button — **not** `quarto::quarto_render()`. The `quarto`
R package is deliberately not a project dependency (D-026).

**Run both products locally before every push.** Two path bugs were caught this way on Day 1
at zero cost; a Connect Cloud build log is a far more expensive place to find a missing file.

## Deploying

Connect Cloud publishes from this repository and re-renders on push (D-027). Content is never
uploaded pre-rendered — the push-to-redeploy cycle is the point of the demonstration.

### When files or packages change, regenerate the manifest

```r
rsconnect::writeManifest(dependencyResolution = "library")
```

`dependencyResolution = "library"` is required: installing `rsconnect` into the project library
desynchronises it from `renv.lock`, and this bypasses the lockfile without recording a
local-only tool in it (I-015).

Then commit `manifest.json` and push. Connect Cloud redeploys automatically.

### Deployment facts worth knowing

- Connect Cloud requires `manifest.json` for R content and **does not read `renv.lock`** — it
  truncates `renv/activate.R` to prevent renv activation (D-018).
- A manifest inside a content item's subdirectory is **ignored**. The root manifest is used,
  and content type comes from the publish request.
- The app runs from `/cloud/project`; the report renders in an ephemeral temporary directory.
  Both are the repository tree root, so **use relative-from-root paths only** (I-016).
- Packages arrive pre-built: roughly two seconds for 94 packages, ten seconds total deploy.
- The free tier publishes from **public repositories only**, and deployed content is publicly
  accessible (I-017).

## Reproducibility, stated accurately

`renv` provides the reproducible local environment and is what `rsconnect::writeManifest()`
reads when pinning package versions. Those pins travel to Connect Cloud inside
`manifest.json`, which is what the platform provisions from. Connect Cloud does not restore
`renv.lock` (D-018).
